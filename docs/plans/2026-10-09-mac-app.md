# Mitosis Mac App (0.1 UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the native SwiftUI Mac app for Mitosis 0.1: main window, guided New Clone flow, per-clone inspector with stats, onboarding, help guide, settings, and menu bar extra. It also needs the small engine additions the UI depends on.

**Architecture:** Add the UI to the existing root Swift package:
- `MitosisUI` (library): every view, the `@Observable` app model and pure presentation logic.
- `MitosisApp` (executable): a three-line `main.swift` that runs `MitosisRootApp`.
- `MitosisSnapshot` (dev-only executable): renders every screen to PNG in light and dark for visual QA.
- `scripts/build-app.sh`: assembles `dist/Mitosis.app`. The icon, Info.plist and resource bundles go in `Contents`; the CLI and launch stub go in `Contents/Helpers`. The bundle gets an ad-hoc signature.

The engine stays UI-free. The UI calls it from background tasks and keeps the main actor responsive.

**Tech Stack:** Swift 6.4 (Swift 6 language mode), SwiftUI on macOS 15+ (`NavigationSplitView`, `.inspector`, `MenuBarExtra`, `Settings`, `Window`, `@Observable`), AppKit where SwiftUI lacks an API (open panels, the workspace, the Dock-icon drop delegate), Swift Testing, `sips`/`iconutil`/`codesign` in the build script.

**Spec:** `docs/specs/2026-10-09-mitosis-design.md`, sections 6 (UI), 8 (errors), and 14 (decisions 7–10, naming, brand). Brand: `docs/brand/BRAND.md`.

## Global Constraints

- **Platform and identity:** minimum macOS 15; app bundle ID `com.mitosis-mac.Mitosis`; app name "Mitosis".
- **Clone names** are always `<App> (<Label>)`. The UI asks for the label only and shows the composed name.
- **Words in the UI:**
  - Support levels: "Works great" (full), "Works with limits" (limited), "Not supported" (unsupported).
  - Modes: "Full clone" (identity), "Compatibility mode" (fallback).
  - Statuses: "Running", "Not running", "Update available", "Original missing".
  - Never show "bundle ID" or "container" in normal UI. They may appear in "Copy details" text only.
- **Voice:** short, plain sentences: what happened, then one next action. Never use "magic", "seamless" or cell-division puns. Error text names the real cause.
- **Look and feel:**
  - System fonts, colors and materials; SF Symbols.
  - Brand blue appears only as the accent: light `#1A7FE0`, dark `#3B9EF0`. These are contrast-safe variants of Primary blue `#41AEF8` for controls. Never tint whole windows.
  - At most one mascot moment per view.
  - Status always uses color + symbol + text.
  - Spacing on an 8 pt rhythm; card corners 10–12 pt.
- **Accessibility:** VoiceOver labels on every control and tile, Reduce Motion respected, light and dark appearance.
- **Keyboard shortcuts:** ⌘N new clone, ⌘F search, ⌘I inspector, Return opens, ⌘⌫ / Delete deletes (with confirmation), ⌘, settings, ⌘? help.
- **Safety:** the original app is never modified. Delete moves things to the Trash. Refresh, restyle and delete refuse while the clone is running and offer "Quit and …".
- **Resources:**
  - No polling that spawns processes on a timer while idle. Running state comes from NSWorkspace notifications.
  - Live usage polls (every 2 s) only while the inspector shows a running clone.
  - Mascot images ship at most 480 px wide.
- **Network:** only the update check (Settings toggle, on by default). Nothing else.

## Review Focus

These are the five likely real-world failures that no automated test covers. Each line names the task that owns it.

- **The user drops something that isn't a usable app** onto the window, Dock icon or picker (a folder, a `.dmg`, an Apple app, a Mitosis clone). Expect a clear inline reason, never a crash (Tasks 7, 9).
- **The clone fails its launch check while the user waits** in the sheet. Expect the oops state with the real reason and "Try compatibility mode" for full clones. Nothing half-made remains (Task 9).
- **The original app is deleted or moved while Mitosis is open.** The tile shows "Original missing" after the app becomes active again; "Find app…" relinks (Tasks 6, 8).
- **Refresh, restyle or delete while the clone runs.** Expect a dialog offering "Quit and Refresh" (or the matching verb), never a silent failure (Tasks 6, 8).
- **Very long labels or emoji/accented labels** (`Ünïcode 🚀`). The composed name previews correctly, validation messages fit, and tiles truncate with a tooltip (Tasks 6, 9).


`ErrorReport`:
```swift
struct ErrorReport { var message: String; var details: String; var issueURL: URL }
static func make(error: Error, appName: String?, appVersion: String?, mode: CloneMode?) -> ErrorReport
```
- `message` is the plain error description with the home folder replaced by `~`. `details` holds the Mitosis version, macOS version, app and version, mode, and the error, also with `~`.
- The issue URL targets `https://github.com/deadhearth01/Mitosis/issues/new` with `template=bug_report.yml` and prefilled `what`, `app`, `macos` and `version` fields.

`Versioning.isNewer(_ candidate: String, than current: String) -> Bool`:
- semver-ish: numeric core, and a prerelease sorts below its release;
- a leading `v` is ignored;
- unparseable input → false.

`RunningTracker` (@MainActor):
- `onChange` fires on NSWorkspace launch and terminate notifications, plus once more 1.5 s later.
- `func running(_ entries: [RegistryEntry]) -> Set<UUID>`:

  - fallback clones: `RunningMonitor.instancePID(of:) != nil`.

  - `restyle(badge:)`;
  - `relink(to:)`;

`AppPrompt` cases:

Previews and snapshots use `AppModel.preview(entries:statuses:running:)`, which never touches disk.

What happens to clones when the original app updates

Apps update all the time. A copy made last month still contains last month's version, so it needs updating too.

Mitosis does that for you.

Quick answer

When the original app updates, Mitosis rebuilds its clones from the new version in the background, keeping each clone's login and data. A clone that's open is rebuilt after you quit it.

How it works

While Mitosis is open: it notices the new version and rebuilds outdated clones that aren't running.

While Mitosis is closed: a small macOS background job watches the original apps (it uses no CPU while waiting) and runs the same update.

Safely: the new clone is built next to the old one and swapped in only when it's complete. If an app is still installing its update, Mitosis waits and tries again later.

Your data stays: logins, settings, and caches live outside the clone, so rebuilding it doesn't touch them.

Prefer to update by hand?

Turn off Settings › General › Update clones automatically. Clones then show Update available, and Refresh rebuilds one. A manual refresh opens the clone once to check that it starts, and puts the previous version back if it doesn't.

Questions

Do clones update themselves?

No. The original app updates as usual; Mitosis then rebuilds its clones from it.

Will I have to sign in again after an update?

No. Your login lives in the clone's data folder, which an update doesn't touch.

Get Mitosis

Free for macOS 15 or later on Apple silicon. Paste in Terminal:

curl -fsSL https://raw.githubusercontent.com/deadhearth01/Mitosis/main/scripts/install.sh | bash

Or with Homebrew: brew install --cask deadhearth01/tap/mitosis
